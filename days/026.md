# Compare Model Runs and Select the Best

## Problem

The xFusionCorp Industries deployment team mandates that every model promoted to serving includes an input schema to ensure that malformed requests are rejected at the boundary, preventing the generation of silent errors. A logging script has been pre-staged along with the necessary data and model. Your task is to attach an MLflow model signature and an input example during the model logging process.

1. The MLflow tracking server is already running on port `5000`. The MLflow UI button at the top of the lab can be opened to view the dashboard.

2. Open `/root/code/log_with_signature.py` in the VS Code editor. It builds a small synthetic two-column training frame (`amount`, `num_txn`), fits a model, and computes its predictions — all already written. Attaching a signature is inherently a code step (there is no UI control for it), so the work is in the script. Two **# TODO** blocks remain inside the `mlflow.start_run()` context:

    - TODO 1: Infer the model signature from the training inputs `X` and the model's predictions `preds`, and bind it to `signature`. Use `mlflow.models.infer_signature(X, preds)`.
    - TODO 2: Log the sklearn **model** under the artefact name **model** with the inferred signature and an **input_example** (pass `X`), using **mlflow**.**sklearn.log_model(...)**, so the logged model carries an enforced input schema.

3. After both TODOs are completed, run the script once:

   ```bash
   python3 /root/code/log_with_signature.py
   ```

The end state must include:

- An experiment named `fraud-signature` with at least one run.
- The logged model carries a signature whose input schema is exactly the columns amount and `num_txn`.
- The schema is enforced: loading the model and predicting with a frame that omits a required column (e.g. `num_txn`) is rejected, while a correctly-shaped frame predicts successfully.

## Solution

1. Update `log_with_signature.py` according to this [codefile](../files/day_26_log_with_signature.py)

    - added signature: `infer_signature(X, preds)`
    - added logging.

2. Run the python script:

    ```bash
    python3 /root/code/log_with_signature.py
    ```

3. Check a new experiment `fraud-signature` has been created and it has at least one run.
