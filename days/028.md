# Fix a Broken MLflow Project and Re-Run It

## Problem

The xFusionCorp Industries ML platform team has packaged their training runs as MLflow Projects to facilitate the reproduction of these runs by any engineer using a single **`mlflow run`** command. A project has been pre-staged at `/root/code/trainer/`. However, the initial run since the lab startup has failed due to the MLproject command line not correctly invoking the trainer; it forwards an incorrectly named flag and omits several parameters required by `train.py`. Your task is to modify the MLproject command to ensure that all parameters are accurately passed to `train.py`. After implementing the necessary adjustments, please execute the project end-to-end twice to confirm that successful runs are recorded.

1. The MLflow tracking server is already running on port 5000. The MLflow UI button at the top of the lab can be opened to view the dashboard; the trainer experiment already contains a FAILED run from the automated run that the lab startup triggered against the broken project.

2. `/root/code/trainer/` contains:

    - `MLproject` – The project descriptor. Its train entry point declares four parameters (`n_estimators`, `max_depth`, `test_size`, `random_seed`), and its `command`: line invokes `train.py`.
    - `train.py` – The trainer entry point. This file is correct and must not be modified; its argparse declares the authoritative flag names (`--n_estimators`, `--max_depth`, `--test_size`, `--random_seed`).

3. The fix is confined to MLproject. Two successful mlflow run invocations of the train entry point must then be recorded in the trainer experiment — one with n_estimators=200 and max_depth=10 supplied as explicit -P overrides, and one that lets both fall back to their declared defaults.

4. The end state must include:

    - The MLproject command forwards every declared parameter (**`n_estimators, max_depth, test_size, random_seed`**) to train.py with flag names that match its argparse declarations.
    - The trainer experiment contains at least two FINISHED runs whose params.n_estimators values differ (one at `200`, one at the default `100`), and the explicit run records `params.max_depth=10` (proving the -P max_depth=10 override reaches train.py).
    - The original FAILED run from the startup is still present – It must not be deleted, because the lab's diagnosis trail depends on it.
    - The failed run's page in the MLflow UI and /tmp/mlflow-run-initial.log both carry the underlying error. Running mlflow run . manually from /root/code/trainer reproduces the same error directly in the terminal.

## Solution

1. Update the [MLproject](../files/day_28_mlproject.yml) project descriptor accordingly.
2. Run the following commands for testing experiments run:

    ```bash
    cd /root/code/trainer
    python3 train.py --n_estimators 200 --max_depth 10
    python3 train.py
    ```

    - 1st one will override default value that described in the MLproject and the 2nd one will run with all default value.
